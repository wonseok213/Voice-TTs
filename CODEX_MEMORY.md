## Project Role
- This project is a local voice cloning app starter for the user's PC
- Main strategy is `XTTS v2` for TTS and optional `RVC` post-processing
- Focus on local inference and clean project structure before heavy model work

## Current Environment Fit
- GPU: `RTX 4060 Ti 8GB`
- RAM: `16GB`
- CPU: `Ryzen 5 7500F`
- Recommended usage is local inference, not full large-scale model training

## Current Structure
- `main.py` for CLI entry
- `main.py` also exposes `serve-web` for a simple Flask UI
- `voice_clone_studio/config.py` for settings loading
- `voice_clone_studio/paths.py` for project directories
- `voice_clone_studio/pipeline.py` for orchestration
- `voice_clone_studio/services/audio_prep.py` for reference-audio handling
- `voice_clone_studio/services/xtts_service.py` for XTTS integration
- `voice_clone_studio/services/rvc_service.py` for RVC integration
- `voice_clone_studio/web_app.py` for the local web UI
- `tools/rvc_passthrough.py` as the current concrete RVC placeholder runtime
- `pkg_resources.py` is a local shim so `TTS` can import cleanly with the current `setuptools` package in this environment
- Web UI now supports multi-file training dataset upload for each profile
- Uploaded audio files are copied into `data/processed/<profile>/training`
- Uploaded video files are stored in `data/raw/<profile>/media`
- If `ffmpeg` is available, uploaded videos are converted into mono 24kHz `.wav` files inside `data/processed/<profile>/training`
- If video extraction fails, the manifest now stores a failure status plus the last visible ffmpeg error text
- The web UI can retry pending video extraction and now shows recent extraction errors per profile
- XTTS generation is now blocked until the local user explicitly stores Coqui TOS acceptance in `config/coqui_tos_agreed.txt`
- The web UI exposes a one-click local `Coqui XTTS 약관 동의 저장` action instead of letting the TTS package ask interactively
- The web UI now shows recent generated `.wav` and `.mp3` files with inline browser playback, latest-file highlighting, direct open links, and download links
- Reference uploads are now normalized to `reference.wav` and a prepared `reference_xtts.wav` is auto-generated by trimming silence and keeping a stronger ~10s speech segment for more stable XTTS cloning
- XTTS now prefers the original normalized `reference.wav` as the primary voice sample and can add up to two extra normalized clips from that profile's training audio as multi-reference conditioning
- XTTS generation now pre-cleans long input text and synthesizes shorter chunks with short pauses to reduce pronunciation collapse on long Korean lines
- `ffmpeg` is now installed inside the `voiceclone310` conda env on this PC, so `.m4a` reference uploads and video-to-audio extraction can run when the app is started from that env
- The first attempt at "strongest segment" selection overfit to loud/emotional parts; the current reference prep now prefers the first clean trimmed speaking window and normalizes level for less distorted voice cloning
- XTTS chunking was relaxed: short text now goes through the normal Coqui path, and only longer text is split with shorter inter-chunk pauses to avoid robotic delivery
- Coqui's outer `Synthesizer` uses an English sentence splitter by default; for Korean XTTS, the app now forces `split_sentences=False` at the wrapper level and uses XTTS's own `enable_text_splitting=True` instead
- Over-aggressive custom XTTS decoding values caused metallic / collapsed speech, so the app now keeps XTTS model defaults and only changes the text-splitting path for Korean
- Current live tuning point for better Korean prosody is a mild `temperature 0.32`, `repetition_penalty 5.0`, and slightly slower `speed 0.94`
- Keep the XTTS stack pinned to `numpy==1.22.0`, `TTS==0.22.0`, `transformers==4.41.2`
- `transformers 5.x` breaks XTTS import/runtime here (`BeamSearchScorer` issue), and `numpy 2.x` breaks SciPy/TTS runtime
- `torch 2.6+` changed `torch.load` to `weights_only=True` by default; `xtts_service.py` now patches `torch.load` back to the legacy default for trusted Coqui XTTS checkpoint loading
- `torchaudio 2.9+` routes `torchaudio.load()` through `torchcodec`; since `torchcodec` is not installed here, `xtts_service.py` patches `torchaudio.load` to a `soundfile`-based fallback before XTTS runs

## Workflow
- Add reference voice first
- Or upload multiple recordings in the web UI to build a profile dataset
- Run XTTS synthesis
- Optionally pass the result through RVC
- Keep model-specific installation steps separate from the app structure
- Replace `tools/rvc_passthrough.py` with a real RVC inference script path once the actual runtime is installed
- The first real XTTS synthesis may download model weights on the user's side
- `ffmpeg` can now be used for automatic video-to-audio extraction during dataset upload
